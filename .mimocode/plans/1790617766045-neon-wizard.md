# Plan: Implement CalDavHandler (replace Google Calendar handler)

## Goal

Implement `CalDavHandler` so `sync()` can drop in CalDAV instead of Google Calendar **without further changes to the synchronisation flow**. Same public API as `CalendarHandler`, same Event correlation, same log/simulate behavior. Invitations go out via **RFC 6638 CalDAV server scheduling** for **future** add/update/delete (matching Google `sendUpdates`).

Also complete the Event↔VEVENT conversion the handler needs (`from_vevent` is buggy and unused; `as_vevent` is missing).

## Context (verified)

- `sync()` only uses: construct → `connect() -> bool` → `list_events()` → `add_events` / `update_events` / `delete_events` ([scout_sync/sync/sync.py](scout_sync/sync/sync.py):558-621).
- `CalendarHandler` fills `self._ids: dict[Event.id -> provider id]` in `list_events()`; update/delete raise `ValueError` if the id is missing; mutators no-op when not connected; add skips events without `datetime`; mutations log with `'(SIMULATED) '` when `SIMULATE`.
- Google invitations: `sendUpdates='all'` only when the event start is still in the future ([scout_sync/sync/google_api.py](scout_sync/sync/google_api.py):95-127).
- Stub `CalDavHandler` already exists ([sync.py](scout_sync/sync/sync.py):343-369) with `from caldav.davclient import get_davclient` — that API is real (caldav 2.x recommended entry point).
- Config keys already exist: `caldav_url`, `caldav_calendar_name`, `caldav_username`, `caldav_password`.
- Deps: `caldav`, `vobject` already listed. `from_vevent` is **icalendar-shaped** (`event.get('dtstart').dt`); `icalendar` is not a dependency yet.

## Decisions (confirmed / picked)

| Topic | Decision |
|---|---|
| Invitations | RFC 6638 server scheduling: correct `ORGANIZER` / `ATTENDEE` / `SEQUENCE` so the server emails invites/updates/cancels. No SMTP. |
| Notify when | Future events only (same rule as Google `sendUpdates`). |
| Event conversion | Fix `from_vevent`, add `as_vevent`. |
| iCalendar lib | Add **`icalendar`** (matches existing `from_vevent` draft; cleaner than vobject for X-props/attendees). Keep `vobject` as-is (caldav may use it). |
| Event.id ↔ resource | **`UID = Event.id`**. `_ids` maps `Event.id` → caldav `Event` object (has `.url`, save/delete). X-MATCH-ID / X-LEAGUE-ID keep `schedule_info`. |
| Constructor | `CalDavHandler(calendar_name)` — drop-in for `CalendarHandler(config.calendar_id)` via `CalDavHandler(config.caldav_calendar_name)`. |
| Client API | `caldav.davclient.get_davclient(url=..., username=..., password=...)`, then select calendar by display name. |
| Private methods | Free-form helpers as needed — **do not** mirror `GoogleCalendarAPI._*` names/signatures. |
| Tests | Offline unit tests (no live CalDAV). Prefer a small in-process fake calendar; use a mock CalDAV server only if setup is trivial. |

## 1. Event ↔ VEVENT conversion

### 1.1 Fix `Event.from_vevent` ([sync.py](scout_sync/sync/sync.py):83-112)

Input: an `icalendar.Event` VEVENT component.

| vevent | Event | Notes |
|---|---|---|
| `UID` | `id` | Required; missing → `logging.warning` + `return None` (same as Google `matchNo`). |
| `X-MATCH-ID` + `X-LEAGUE-ID` | `schedule_info` | Both required, else `None`. |
| `DTSTART` (`.dt`) | `datetime` via `arrow.get(...)` | Preserve tz; if naive, localize with `TIMEZONE`. |
| `LOCATION` | `location` | |
| `SUMMARY` minus `'Scouting '` | `league` | |
| `DESCRIPTION` | `opponent` | |
| `ATTENDEE` | `scouters` | Skip `PARTSTAT=DECLINED`; `mailto:` strip; map via `Event._names`. |

Bug fixes in the draft:

- `cls.__names[email]` → `cls._names[email]` (name-mangling bug).
- Null-check: `match_id is None or league_id is None` (draft tests `match_id` twice).
- `id` from `UID`, not `x-match-id`.
- Restore declined-attendee filter (`PARTSTAT=DECLINED`).

Helper for getting a single property value (icalendar may return a list): local function inside `from_vevent` or a tiny module-level helper used by both directions — keep it local if only used once per direction.

### 1.2 Add `Event.as_vevent(self, sequence=0, notify=True)`

Returns an `icalendar.Event`. Maps the Google write contract:

```
UID: self.id
DTSTART / DTEND: self.datetime / +2h  (tz-aware, TIMEZONE)
SUMMARY: 'Scouting ' + (self.league or '')
DESCRIPTION: self.opponent
LOCATION: self.location
X-MATCH-ID / X-LEAGUE-ID: from schedule_info (if set)
SEQUENCE: sequence
```

**Attendees** (only if `self.scouters is not None`; empty list clears attendees):

```
ATTENDEE;CN=<name>;CUTYPE=INDIVIDUAL;ROLE=REQ-PARTICIPANT;
  PARTSTAT=<NEEDS-ACTION|ACCEPTED>;RSVP=<TRUE|FALSE>:mailto:<email>
```

- `notify=True` (future): `PARTSTAT=NEEDS-ACTION`, `RSVP=TRUE` → invitation-like.
- `notify=False` (past): `PARTSTAT=ACCEPTED`, `RSVP=FALSE` → approximate Google `sendUpdates='none'`.
- Unknown scouter names: `logging.warning`, skip (same as Google).

**Organizer** (needed for RFC 6638 scheduling):

```
ORGANIZER;CN=<username>:mailto:<caldav_username>
```

Only when `config.caldav_username` looks like an email (`'@' in ...`); otherwise omit and let the server attach the principal.

**Reminder** (Google popup 360 minutes):

```
BEGIN:VALARM
TRIGGER:-PT6H
ACTION:DISPLAY
DESCRIPTION:Scouting
END:VALARM
```

Also wrap as `icalendar.Calendar` with `METHOD` omitted (stored objects must not carry iTIP METHOD; the server generates REQUEST/CANCEL).

## 2. `CalDavHandler` — identical API

Replace the stub ([sync.py](scout_sync/sync/sync.py):343-369).

```python
class CalDavHandler:
    def __init__(self, calendar_name):
        self._calendar_name = calendar_name
        self._calendar = None
        self._client = None
        self._ids = None

    def connect(self) -> bool
    def add_events(self, events) -> None
    def update_events(self, events) -> None
    def delete_events(self, events) -> None
    def list_events(self) -> list[Event] | None
```

**Only the public `CalendarHandler` surface is fixed** (`__init__`, `connect`, `list_events`, `add_events`, `update_events`, `delete_events`). Private helpers are whatever the CalDAV implementation needs — they do **not** need to match `GoogleCalendarAPI._connect_to_service` / `_insert_event` / etc. No shared base class.

Suggested private shape (adjust freely during implementation):

- open client + select calendar + smoke-test read (used by `connect`)
- parse one caldav resource → `Event` + read `SEQUENCE`
- write/save one VEVENT (insert vs update)
- delete one resource
- `_should_notify(*datetimes)` for the future-only rule

### 2.1 `connect()` — error handling + logging (explicit requirement)

Match `CalendarHandler.connect()` contract (`True`/`False`), expand beyond the stub:

```python
def connect(self):
    try:
        self._connect_to_service()
    except Exception as e:
        logging.error(
            f"Connection to CalDAV calendar {self._calendar_name} failed: {e}")
        return False

    logging.info(f"Connected to calendar: {self._calendar_name}")
    return True
```

`_connect_to_service()` responsibilities:

1. `client = get_davclient(url=config.caldav_url, username=..., password=...)`.
2. Raise `ValueError` if client is `None` or URL/username/password missing.
3. `principal = client.principal()`; list calendars (`principal.calendars()`).
4. Select by display name (`calendar.name` / `get_display_name()`) equal to `self._calendar_name`. Raise `ValueError` listing available names if not found.
5. Smoke-test with a calendar read (e.g. `self._calendar.events()` or `date_search` of a one-day window).
6. `logging.warning` if `client.supports_scheduling()` is False (invitations will not be emailed by the server).
7. Store `self._client`, `self._calendar`.

Use module-level `logging` f-strings like the rest of `sync.py`. Quiet noisy third-party loggers if needed (`logging.getLogger('caldav').setLevel(logging.ERROR)`).

### 2.2 Notification rule (Google `sendUpdates` parity)

```python
def _should_notify(self, *datetimes):
    now = arrow.now(TIMEZONE)
    return any(dt is not None and dt > now for dt in datetimes)
```

| Operation | `notify` when |
|---|---|
| insert | `event.datetime > now` |
| update | `old_event.datetime > now or event.datetime > now` |
| delete | `event.datetime > now` |

`notify` only affects attendee `PARTSTAT`/`RSVP` (see §1.2). SEQUENCE and ORGANIZER stay correct so the server can schedule. True silent past-event email suppression is not fully controllable via RFC 6638; this matches Google as closely as the protocol allows.

### 2.3 `list_events()`

- No-op → `return None` if `self._calendar is None` (same as `if not self._service`).
- Iterate `self._calendar.events()` (all objects).
- Parse each to VEVENT → `Event.from_vevent`; drop `None` (invalid / no UID).
- `self._ids[event.id] = caldav_event_object`.
- Return `list[Event]`.

### 2.4 `add_events(events)`

- Guard not-connected.
- For each `ev`: skip + `logging.warning` if `ev.datetime` is None (same message style as Google).
- `notify = self._should_notify(ev.datetime)`.
- `ical = ev.as_vevent(sequence=0, notify=notify)` wrapped in a Calendar.
- `self._calendar.save_event(ical)` (or `add_event`).
- Register in `self._ids` if easy (`self._ids[ev.id] = created`).
- `logging.info(f"{'(SIMULATED) ' if SIMULATE else ''}Added event to calendar:\n\t\t{ev}")`.
- If `SIMULATE`: build only, do not save.

### 2.5 `update_events(events)`

- Guard not-connected.
- For each `ev`: `resource = self._ids.get(ev.id)`; if missing → `ValueError(f"Can not update event {ev.id}: event is not in calendar!")`.
- Read current ical from `resource` → `old_ev = Event.from_vevent(...)` for the log line (same as Google).
- Read current `SEQUENCE` from the stored VEVENT (default 0); write `as_vevent(sequence=old_sequence + 1, notify=...)`.
- `notify = self._should_notify(old_ev.datetime if old_ev else None, ev.datetime)`.
- Save onto `resource` (`resource.save()` / `resource.update(...)`).
- Log: `Updated event in calendar:\n\t-\t{old_ev}\n\t+\t{ev}` with `(SIMULATED) ` prefix.
- SEQUENCE increment is what makes RFC 6638 servers send **updated invitations**.

### 2.6 `delete_events(events)`

- Guard not-connected.
- Same `_ids` lookup / `ValueError` message pattern (`Can not delete event ...`).
- `old_ev = Event.from_vevent(...)` for logging.
- `notify = self._should_notify(old_ev.datetime if old_ev else None)` — only used for logging context / future refinement; DELETE of a scheduling object by the organizer is what triggers server **CANCEL** invitations.
- `resource.delete()` unless `SIMULATE`.
- Log `Deleted event in calendar:\n\t\t{old_ev}`.

## Risks / notes

- **Past-event “silent” updates** cannot be fully guaranteed with pure RFC 6638; server may still notify on create/delete. RSVP/PARTSTAT approximation is intentional.
- **Server scheduling support varies** (Radicale often has no email; Nextcloud/Baikal/SOGo do). `supports_scheduling()` warning in `connect()` surfaces this.
- **`principal().calendars()` display-name matching** must handle servers that omit displayname (fall back to URL/name attr).
- **`scouters is None`** must still omit attendees on write (preserves existing attendees on update) — same as Google `as_calendar_event`.
- Keep `schedule_info` X-props intact; `sync()` delete guards depend on them ([sync.py](scout_sync/sync/sync.py):605-617).
- Fake-calendar tests cover our API surface only; they do not prove a particular server will email invitations.
